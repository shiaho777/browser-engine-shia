# RFC 0026 — Ruby: display-role partition, annotation stacking, atomic baseline

Status: implemented (single-level ruby, documented bounds)
Packages: `generator` (`css-properties.data.ts` — ruby display keywords),
`layout` (`index.ts` — `layoutRuby` + `rubyBaselineOff` + inline-level
membership), `cascade` (`index.ts` — font-size `<percentage>` fix), `cli`
(`stylesheets.ts` UA rules; `ruby.test.ts`)

## Decision

**Ruby children partition by COMPUTED `display`, not by tag.** CSS Ruby
§2.2 gives `rb`/`rt`/`rtc`/`rp` internal display values (`ruby-base`,
`ruby-text`, `ruby-text-container`, none) precisely so the layout roles
survive author re-tagging — an element `display:ruby-text` behaves as an
annotation whatever its tag. The partition therefore reads the raw
computed `display` string:

- `none` (`<rp>`) → dropped entirely;
- `ruby-text` → an annotation item;
- `ruby-text-container` → each `ruby-text` child is an annotation, and any
  bare text inside becomes an implicit annotation carried by the rtc's
  own style;
- `ruby-base` / `ruby-base-container` → children recurse into base items;
- anything else (bare text, ordinary inlines, a nested `display:ruby`)
  → a base item shaped with its own element style.

**Each item is its own fragment.** `<rb>`/`<rt>`/text children emit
separate text fragments (node = the source element), so per-item
`font-size`/`color`/letter-spacing survive — the UA `rt { font-size: 50% }`
is real cascade, not a hard-coded factor, and mixed-size base spans are
baseline-aligned against each other.

## Geometry

The ruby box shrink-wraps to `max(base extent, widest annotation)`. The
narrower run is centred (`ruby-align: space-around`/`center`) or flushed
to inline-start (`start`) — "inline-start" is virtual-x start, so the same
code produces the correct logical edge inside vertical writing modes after
the RFC 0025 transposition.

Annotations stack on their `ruby-position` side — `over` above the base
line, `under` below, `inter-character` approximates to `over` — and grow
the box's block extent, so the line box has room: annotation-above-base
makes the atomic 24px tall against a 16px base, matching real-browser
line growth. The atomic's baseline is the **base run's** baseline
(`rubyBaselineOff` scans the registered children for the first text run
that is not an `rt`/`rtc` node) — the annotation pokes above the line top
instead of dragging the base glyph off the line baseline.

## `display:ruby` is inline-level

`LAYOUT_DISPLAYS` gains `ruby` (dispatch to `layoutRuby`); the internal
roles fall through `readDisplay`'s default to `inline`, which is exactly
CSS Ruby's inlinification rule for stray `<rt>` outside a ruby. And
`isInlineLevelChild` accepts `display:ruby` so a `<ruby>` packs into a
line box between text runs — `前<ruby>漢<rt>かん</rt></ruby>後` is one
line of three members, not three block boxes.

## Cascade fix that ruby required

`rt { font-size: 50% }` surfaced a real bug: `resolveOne` keeps `%`
specified-lengths for used-value resolution (correct for `width`, wrong
for `font-size`, whose percentage resolves against the *parent's* font
size — CSS Fonts 4 §4.1). The computed `fontSize` ended up a
`specified-length` object → NaN in layout. `resolveFontSizeLength` now
resolves `%` at cascade time for that one property — which also fixes
author `font-size: 150%` everywhere, not just inside ruby.

## UA sheet

```
ruby { display: ruby }         rb  { display: ruby-base }
rt  { display: ruby-text;      rbc { display: ruby-base-container }
      font-size: 50% }         rtc { display: ruby-text-container }
rp  { display: none }
```

## Evidence

- `ruby.test.ts`: **14/14** — partition order (rt/rtc/rb/rbc/rp), box
  sizing both directions, `space-around` vs `start` alignment, `under`
  stacking, rtc's stacked annotations + bare-text implicit annotation,
  inline flow between text runs with line growth, the base-run atomic
  baseline, rt's own `font-size:50%` cascade, `vertical-rl` annotation
  landing on the base's right side, stray-rt inlinification,
  annotation-only ruby, and the `font-size:150%` cascade regression.
- `npm run ci`: **1566/1566** (+14), WPT 462/462 — zero regressions.

## Bounds

1. **No inter-segment pairing**: `rb1 rb2 | rt1 rt2` produces one base run
   with both annotations stacked, not two side-by-side base/annotation
   pairs. Per-segment `<rb>`↔`<rt>` pairing is the missing half of the
   spec table.
2. **`rtc` on the under side stacks, it does not form a second parallel
   track**: two rt's inside one `rtc` render one above the other.
3. **`ruby-align: space-between` ≈ centre** — no intra-annotation
   justification/stretch; `space-around` does not distribute half-width
   edge gaps either.
4. **No annotation overhang into neighbours**: a wider annotation grows
   the ruby box instead of overhanging adjacent inline content (the CSS
   overhang rules are not modelled), and annotations never spill past the
   line edge.
5. **Nested `display:ruby` flattens to base text** — the inner ruby's
   own annotations are lost inside the outer base (it still renders as a
   box; it just doesn't pair). Ruby *inside* an annotation likewise
   collapses.
6. **`inter-character` ≈ `over`** — the rotated side annotation used for
   Zhuyin is not produced.
7. **`rp` is display:none, not a fallback-rendered paren** — the
   pre-ruby-browser fallback presentation (parens inline around rt) is
   not a mode this engine has.
