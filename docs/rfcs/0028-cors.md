# RFC 0028 — CORS: safelists, OPTIONS preflight + cache, response filtering, `crossorigin`

Status: implemented (Fetch CORS core; documented bounds)
Packages: `guest` (`cors.ts` — policy machinery; `network.ts` — enforcement
inside the stack), `cli` (`event-loop.ts` — loop-level mode semantics; XHR
credentials wiring; `loader.ts` — `crossorigin` map), `app` (`page.ts`,
`engine-runtime.ts` — attribute map + dedicated font channel)

## Decision

**CORS lives INSIDE the network stack** (`createBrowserNetworkStack`). That
is the only layer that sees every redirect hop, owns per-hop headers, and
can issue real OPTIONS through the same transports (curl or undici), so
TLS/proxy behavior matches actual requests.

### Request side

- `mode`: `navigate` | `cors` | `no-cors` | `same-origin`.
  - `same-origin` + cross-origin target → rejects before the wire.
  - `no-cors` → every non-safelisted caller header is stripped on every
    hop; a non-safelisted method rejects outright.
  - `cors` → `Origin` rides the request; a preflight runs when the request
    isn't safelisted; EVERY hop's response must carry a matching
    `Access-Control-Allow-Origin` — a redirect into a foreign origin
    without ACAO fails the chain, so an `ACAO:*` first hop can't launder a
    foreign payload.
- `credentials`: `omit` suppresses Cookie/Authorization everywhere
  (caller-supplied AND jar-attached); `same-origin` suppresses them when a
  hop leaves the initiator's origin; `include` attaches credentials even
  cross-origin (jar SameSite rules still apply on top). Redirect
  credential-strip is now a consequence of the credentials mode rather
  than an unconditional rule — `include` keeps credentials across a
  cross-origin redirect, which is the spec behavior.

### Preflight + cache

- Trigger: `mode === "cors"` && cross-origin && (non-safelisted method OR
  any non-safelisted header). Forbidden header names (cookie, host, sec-*,
  proxy-*, origin, …) never trigger — guest code can't set them; they only
  matter to the credentials channel.
- Preflight = OPTIONS with `Origin`/`Access-Control-Request-Method`/
  `-Request-Headers` (sorted, lowercased, non-safelisted names only) on the
  SAME transport as the real request, no credentials.
- Success: 2xx + matching ACAO + ACAM covers the method (`*` allowed) +
  ACAH covers every non-safelisted name (`*` covers all EXCEPT
  `authorization`, per spec) + ACC:`true` when credentialed.
- `CorsCache` per stack, keyed (origin, url, credentials), honoring
  `Access-Control-Max-Age` (default 5s, capped 600s like Chromium).

### Response side (filtered responses)

- `no-cors` → opaque: status 0, empty headers, empty body, `type:"opaque"`.
- `cors` → `type:"cors"` with headers filtered to the exposure safelist ∪
  `Access-Control-Expose-Headers` (`*` ⇒ all).
- `same-origin`/default → `type:"basic"`, headers unfiltered.
- Guest-visible rejections use the realm's own `TypeError`, so
  `e instanceof TypeError` holds inside the vm context.

### Element plumbing

- `crossorigin` attribute (HTML CORS settings): absent ⇒ the element's
  legacy mode; `anonymous`/empty/invalid ⇒ `mode:"cors",
  credentials:"same-origin"`; `use-credentials` ⇒ `credentials:"include"`.
- `collectCrossoriginSettings(dom)` maps resolved URLs of
  `img[src|srcset]`/`source`/`link[stylesheet]`/`script[src]` marked with
  the attribute; `networkStackToFetchFn`'s new `requestFor(url)` hook
  applies per-URL mode/credentials — image prefetch, stylesheet prefetch,
  and script loads all ride it.
- `@font-face` sources are ALWAYS CORS-anonymous fetches (CSS Fonts 4
  §4.9): a dedicated `fontFetch` channel (`mode:"cors"`,
  `credentials:"same-origin"`) is plumbed through renderDom and persisted
  on `PageState` so repaints/edit renders keep the semantics.
- XHR sends `mode:"cors"` + `credentials` from `withCredentials` — it
  inherits the full machinery through the shared fetch path.

## Bounds (honest)

- **The virtual (`Map`) transport can't run real CORS** — there are no
  server headers to check. It enforces the pure client-side parts
  (`same-origin` rejection, `no-cors` opaqueness); a `cors`-mode request
  against a fixture stays permissive. Real enforcement requires the stack
  path (`browserFetch`/`networkStackToFetchFn`).
- **Redirected preflights are not re-preflighted** — a 3xx OPTIONS
  response fails the status check (conservative block).
- **`Access-Control-Expose-Headers: *` under credentials** is treated as
  covering all names; spec counts `*` literally there — a documented
  approximation.
- **Preflight cache ignores `Vary`/`Access-Control-Request-*` soft
  invalidation** beyond keying on (origin,url,credentials).
- **Private Network Access** (`Access-Control-Request-Private-Network`)
  is not modeled.
- **No `Timing-Allow-Origin`, no `Opaque-Redirect` filtered type**;
  `redirect:"manual"` remains a stack-level (not per-request) option.
- **Elements without `crossorigin` keep legacy semantics** — an
  unmarked `<img>` is a `no-cors`+`include` fetch with an opaque result;
  cross-origin canvas taint tracking is not yet modeled at paint.
